# Сценарии — контракт для интерфейса

Документ описывает, как интерфейс сценариев в `src/GhostClick.App/wwwroot` (редактор — в
`scenario.js`, экран «Настройки → Сценарий» по макету GhostClick v4) разговаривает с мостом и
движком: блоки, формат данных, сообщения, состояния блоков.

**Сценарий** — конструктор в духе «Команд» на iOS: пользователь собирает список блоков, и по
хоткею запуска они выполняются сверху вниз. Сценарий — это не отдельная сущность, а **тип
профиля**: у него те же имя, хоткеи, аварийная остановка, переключатели безопасности, dry run,
сохранение, отмена и дублирование, что и у обычного кликера.

## Как посмотреть без Windows

Откройте страницу через любой статический сервер (`python -m http.server` в папке `wwwroot`).
Страница не найдёт WebView2 и подключится к превью-хосту из `host.js`: он отвечает на те же
сообщения, что и мост, и по-настоящему «проигрывает» сценарии — с паузами, повторами,
подсветкой текущего блока и ошибками. В меню профилей есть три демо:

| Профиль | Что показывает |
| --- | --- |
| «Рыбалка — сценарий» | бесконечный прогон, случайное ожидание, выключенный блок |
| «Ферма — сценарий» | все типы блоков, повтор с блоками внутри, «Зажать … Отпустить», выключенный «Стоп» |
| «Черновик сценария» | состояние «ошибка»: «Нажать» без клавиши и «Повторить» с нулём повторов |
| «Магазин — сценарий» | пример из макета v4: метка, «Ждать клавишу» (нажмите Space на странице), «Удержать», «Отпустить» |

Превью проигрывает и тестовый прогон. С параметром `?update=1.4.0` в адресе превью показывает
окно обновления и имитирует загрузку.

## Блоки

У **каждого** блока есть:

| Поле | Тип | Смысл |
| --- | --- | --- |
| `type` | строка | тип блока, см. таблицу ниже |
| `id` | строка | постоянный идентификатор, уникальный в сценарии. **Создаёт страница** при добавлении блока (подойдёт `crypto.randomUUID()` или 8 случайных hex-символов) и не меняет при перемещении. По нему движок сообщает, какой блок выполняется, а проверка — где ошибка |
| `enabled` | `true` / `false` | выключенный блок пропускается вместе со всем, что внутри него |
| `label` | строка или `null` | подпись пользователя; если её нет, показывайте название типа |

| `type` | Название | Что делает | Настройки |
| --- | --- | --- | --- |
| `press` | **Нажать** | Нажимает и отпускает клавишу или кнопку мыши. Модификаторы нажимаются вокруг. «Случайная длительность нажатия» из безопасности — ±30 % вокруг длительности | `input` — клавиша/кнопка с модификаторами; `click` — `single` / `double` (двойной: два нажатия с паузой двойного клика профиля, одно действие); `dur` — `profile` (как клики профиля: первое кликающее действие, без него 30 мс) или `own` (`press` мс); `press` — своя длительность, мс; `at` — точка `{x, y}`: если задана, курсор сначала едет туда |
| `hold` | **Зажать** | Нажимает и **оставляет нажатой** (бег с зажатой W) | `input`, `at` — как у «Нажать» |
| `release` | **Отпустить** | Отпускает то, что зажал «Зажать» выше по сценарию | `input`, `at` — как у «Нажать» |
| `holdFor` | **Удержать** | Нажимает, держит фиксированное или случайное время, отпускает; одно действие | `input`; `ms`; `rand`, `minMs`, `maxMs` — как у «Ждать». Интерфейс показывает секунды |
| `scroll` | **Прокрутить** | Колёсико вверх или вниз на N щелчков; одно действие | `dir` — `up` / `down`; `count` — щелчков, от 1; `at` |
| `drag` | **Перетащить** | Курсор в точку `at`, кнопка вниз, ведёт до `to`, кнопка вверх; одно действие | `input` — кнопка мыши (`Mouse1`…`Mouse3`); `at` — откуда; `to` — куда; `speed` — `slow` (1 с), `mid` (0,5 с), `fast` (0,25 с) |
| `type` | **Ввести текст** | Печатает строку посимвольно Юникодом — раскладка не важна; одно действие | `text`; `ms` — пауза между символами |
| `move` | **Переместить** | Ведёт курсор в точку | `to` — точка; `how` — `instant` / `smooth` (за `ms` мс); без `how` — как настроено «Движение курсора» профиля (так читаются старые блоки) |
| `shift` | **Сдвинуть** | Смещает курсор от того места, где он сейчас, по движению профиля | `dx`, `dy` — пиксели, могут быть отрицательными |
| `wait` | **Ждать** | Пауза. Заменяет автоматическую паузу между шагами (см. ниже) | `ms`; `rand` — случайно из диапазона `minMs`…`maxMs`; `unit` — `ms` / `s`: только как интерфейс показывает время, хранится всегда в мс |
| `waitKey` | **Ждать клавишу** | Сценарий стоит, пока пользователь не нажмёт клавишу (лишние модификаторы не мешают). Нажатия самого кликера не считаются | `input` |
| `repeat` | **Повторить** | Выполняет блоки внутри себя N раз или бесконечно | `mode` — `fixed` (N раз) или `inf`; `count` — N; `blocks` — блоки внутри |
| `random` | **Случайно одно из** | Каждый раз выполняет один случайный включённый блок изнутри | `blocks` |
| `stop` | **Стоп** | Завершает весь прогон, включая оставшиеся прогоны сценария | — |
| `label` | **Метка** | Заголовок-разделитель, ничего не выполняет | `text` |

Значения, которые получает блок, если поле не прислано: `wait` — 1000 мс, диапазон
500–1500 мс, `rand: false`; `repeat` — `fixed`, 2 раза, пустой; `move` — `{0, 0}`; `press` —
`single`, `own`. У блоков с клавишей без `input` клавиша **не выбрана** (это ошибка, а не ЛКМ).
Новые блоки страница создаёт сама, со значениями из макета (`DEFAULTS` в `scenario.js`).

### Как выполняется сценарий

* Блоки идут сверху вниз; выключенные пропускаются вместе с содержимым, «Метка» — всегда.
* **Пауза между шагами.** Между двумя шагами, между которыми нет «Ждать», движок сам вставляет
  паузу `stepDelay` (по умолчанию 100 мс). «Ждать» её заменяет — поэтому «Ждать 0 мс»
  означает «следующий шаг сразу». Пауза ставится и между итерациями повтора, и между прогонами.
* **Прогоны.** Весь сценарий выполняется 1 раз, N раз или бесконечно (`script.repeat`).
* «Стоп» внутри повтора завершает **весь** прогон, а не только повтор.
* **Пауза и остановка отпускают всё.** На паузе движок отпускает всё, что держат блоки
  («Зажать», недоделанные «Удержать» и «Перетащить»), и нажимает снова на «Продолжить». На
  стопе, аварийной остановке, ошибке и выходе — отпускает навсегда.
* Блоки после бесконечного «Повторить» никогда не выполнятся — это не ошибка, но интерфейс
  может это подсказать.
* Из профиля сценарий берёт: хоткеи (`bind`), режим «Переключение / Удержание» (`mode`),
  аварийную остановку, переключатели безопасности (`flags`): разброс точки (`jitter`) — для
  точек `at`/`to`, случайную длительность нажатия (`holdRandom`, ±30 % вокруг `press`) — для «Нажать», остановка при движении
  мыши, «Только активное окно». Как и у кликера, после прогона курсор возвращается туда, где
  был до старта, а всё, что осталось зажатым, отпускается. Поля кликера (`actions`, `points`, `target`, `delay`,
  `repeat`, `count`, `click`) на сценарий **не влияют**, но хранятся: переключение `kind` туда
  и обратно ничего не теряет.
* **Счётчик «кликов»** считает действия: каждое «Нажать», «Отпустить», «Удержать»,
  «Прокрутить», «Перетащить» и «Ввести текст» (перетаскивание «Зажать → Переместить →
  Отпустить» — одно действие). Лимит действий профиля считает так же.
* «Бесконечно» (прогон или бесконечный «Повторить» внутри) снимает скрытый лимит времени, как
  «Повтор: Бесконечно» у кликера.

## Формат данных

Сценарий — часть того же среза профиля `data`, что приходит в `init` / `profile` и уходит в
`setProfile`. Добавлены два поля: `kind` и `script`. Страница, как и сейчас, держит срез у
себя, меняет его и после каждого изменения отправляет **целиком**.

```json
{
  "kind": "script",
  "bind": { "toggle": { "mods": [], "key": "F6" }, "pause": { "mods": [], "key": "F7" },
            "panic": { "mods": ["Ctrl"], "key": "F12" }, "point": { "mods": [], "key": "F9" } },
  "mode": "toggle",
  "flags": { "jitter": true, "holdRandom": true, "stopOnMouseMove": false, "activeWindowOnly": true },
  "…": "остальные поля кликера, как раньше",
  "script": {
    "repeat": "fixed",
    "count": 3,
    "stepDelay": 100,
    "blocks": [
      { "type": "move", "id": "a1f0c3d2", "enabled": true, "label": "К грядке", "to": { "x": 640, "y": 360 } },
      { "type": "repeat", "id": "9b7e1c44", "enabled": true, "label": "Собрать урожай", "mode": "fixed", "count": 5,
        "blocks": [
          { "type": "press", "id": "5c2d8e01", "enabled": true, "label": "Сорвать",
            "input": { "mods": [], "key": "Mouse1" }, "at": { "x": 640, "y": 360 } },
          { "type": "wait", "id": "e40b77aa", "enabled": true, "label": null, "ms": 300, "rand": true, "minMs": 250, "maxMs": 400 }
        ] },
      { "type": "hold", "id": "0d9f6b13", "enabled": true, "label": "Идти вперёд", "input": { "mods": [], "key": "KeyW" } },
      { "type": "wait", "id": "77c1a9e5", "enabled": true, "label": null, "ms": 800, "rand": false, "minMs": 500, "maxMs": 1500 },
      { "type": "release", "id": "c3a54f20", "enabled": true, "label": "Остановиться", "input": { "mods": [], "key": "KeyW" } },
      { "type": "press", "id": "2b8e6d90", "enabled": true, "label": "Открыть сундук", "input": { "mods": ["Shift"], "key": "KeyE" } },
      { "type": "stop", "id": "f1e2d3c4", "enabled": false, "label": "Только один круг" }
    ]
  }
}
```

| Поле | Значения |
| --- | --- |
| `kind` | `clicker` — обычный кликер, `script` — сценарий |
| `script.repeat` | `once` — 1 раз, `fixed` — `count` раз, `inf` — бесконечно |
| `script.count` | число прогонов для `fixed`, от 1 |
| `script.stepDelay` | пауза между шагами, мс, от 0 |
| `script.blocks` | блоки верхнего уровня |

* `script` приходит **всегда**, и у кликера тоже (обычно с пустым `blocks`).
* Поле, которое к типу блока не относится или не задано, в данных от моста **отсутствует**
  (например, у `press` без точки нет `at`, у `stop` нет ничего, кроме общих полей). Считайте
  отсутствующее поле равным `null`; отправлять можно и `null`, и без поля.
* **Клавиши и кнопки** (`input`, как в `bind` и `actions`): `key` — `KeyboardEvent.code`
  (`KeyQ`, `Digit1`, `F6`, `Space`, `ShiftLeft`…) или `Mouse1`…`Mouse5` (ЛКМ, ПКМ, СКМ, X1, X2);
  `mods` — массив из `Ctrl`, `Shift`, `Alt`, `Win`.
* **Точки** (`at`, `to`) — пиксели виртуального рабочего стола, могут быть отрицательными на
  мульти-мониторе. Удобно заполнять хоткеем «Добавить точку» (F9): мост присылает
  `pointAdded {x, y}`, и страница кладёт точку в выбранный блок.
* Блок неизвестного типа (сохранён более новой версией GhostClick) приходит со своим `type` и
  общими полями. Его можно двигать, выключать, подписывать и удалять — его данные мост хранит
  сам и не теряет; запустить сценарий с ним нельзя (см. «Ошибки»).

## Сообщения

JSON-сообщения через `host.send(...)` / `host.listen(...)`, как и всё остальное. Ниже — только
то, что касается сценариев; остальной протокол не изменился (`docs/DEVELOPMENT.md`).

### Страница → мост

| Сообщение | Что делает |
| --- | --- |
| `setProfile {data}` | Как раньше; `data` теперь включает `kind` и `script`. Смена `kind` — это просто `setProfile` с другим `kind` |
| `newProfile {kind}` | `kind: "script"` создаёт и сохраняет новый сценарий «Сценарий N» с одним блоком «Нажать ЛКМ» (пустой сценарий сохранить нельзя). Без `kind` — новый кликер, как раньше |
| `testRun {from?}` | **Тестовый прогон**: сценарий текущего профиля (какой бы ни был тип профиля) идёт в dry run — ввод не уходит в систему — сверху или, с `from`, от этого блока до конца, один раз. Переключатель dry run и профиль движка потом возвращаются как были |
| `testStop` | Останавливает тестовый прогон |
| `start`, `stop`, `pause`, `resume`, `panic`, `saveProfile`, `revertProfile`, `duplicateProfile`, `loadProfile`, `setDryRun`, `listen` | Без изменений, работают и для сценариев |

### Мост → страница

| Сообщение | Что нового |
| --- | --- |
| `init` | `profile.issues` — проблемы профиля (см. «Ошибки»); `runtime.block` — текущий блок или `null` |
| `profile` | `profile.issues` — проблемы загруженного / сохранённого профиля |
| `issues {issues}` | Проблемы изменились после `setProfile`. Приходит только при изменении; пустой массив — всё исправлено |
| `block {block}` | Прогон сценария перешёл к другому блоку; `null` — прогон закончился |
| `state` | Как раньше, плюс `block` — текущий блок или `null`; `pointIndex` у сценария всегда `-1` |
| `toast` | Ошибка запуска или сохранения называет блок: ««Собрать урожай»: Количество повторов должно быть не меньше 1» |
| `log` | «Старт · сценарий, 8 блоков», затем, как у кликера, «Выполнено · 21 клик» / «Остановлено · …» / «Аварийная остановка · …» |
| `test {active, completed?}` | Тестовый прогон начался (`active: true`) или закончился; `completed` — дошёл до конца, а не остановлен |
| `testError {block, message}` | Тестовый прогон не начался: ошибка в блоке `block` (страница раскрывает его) или вне блоков (`block: null`) |

**Текущий блок** (`block` в сообщениях `block` и `state`):

```json
{
  "id": "5c2d8e01",
  "pass": 2, "passes": 3,
  "loops": [ { "id": "9b7e1c44", "iteration": 4, "count": 5 } ]
}
```

| Поле | Смысл |
| --- | --- |
| `id` | блок, который выполняется |
| `pass`, `passes` | номер прогона сценария (с 1) и сколько их всего; `passes: null` — бесконечно |
| `loops` | все «Повторить» вокруг блока, от внешнего к внутреннему: `id` повтора, `iteration` (с 1), `count` (`null` — бесконечный). По ним удобно показать «4 / 5» на заголовке повтора |

* Сообщение `block` приходит, когда блок **начинается** — сразу, даже если блок ещё ждёт
  (окно под курсором — сам GhostClick, или прогон на паузе). Во время автоматической паузы
  между шагами текущим остаётся предыдущий блок.
* Каждый проход блока — новое сообщение: «Нажать» внутри повтора на 5 итераций придёт 5 раз
  (с разным `iteration`).
* Если блоки сменяются быстрее, чем страница успевает рисовать, мост присылает только
  последний — короткие блоки могут «проскочить» без подсветки. Счётчики при этом верные.
* Пока выполняется «Ждать клавишу», текущий блок — он; страница пишет «Жду Space — нажмите,
  чтобы продолжить».

## Состояния блока

| Состояние | Когда | Как узнать |
| --- | --- | --- |
| Обычный | — | — |
| **Активен** | прогон сейчас на этом блоке | `block.id === блок.id` из последнего `block` / `state`. «Повторить», внутри которого идёт работа, — в `block.loops`: удобно подсветить его слабее и показать счётчик итераций |
| **Выключен** | `enabled: false` | у самого блока или у любого «Повторить» над ним. Выключенный блок не выполняется и **не проверяется** на ошибки (кроме `id`) — так пользователь «паркует» недоделанный блок |
| **Ошибка** | у блока есть проблема | в `issues` есть элемент с `block === блок.id`; `message` — текст, `field` — какое поле подсветить. Блоки размечаются ошибками и у профиля типа «Обычный» — тестовый прогон всё равно их играет |

Активным блок с ошибкой быть не может: сценарий с ошибками не запускается. Неизвестный блок
(из новой версии) всегда в состоянии «Ошибка», пока включён.

## Ошибки

Элемент `issues`:

```json
{ "block": "9b7e1c44", "path": [1], "field": "count", "message": "Количество повторов должно быть не меньше 1" }
```

| Поле | Смысл |
| --- | --- |
| `block` | `id` блока с проблемой; `null` — проблема не в блоке (весь сценарий или остальной профиль) |
| `path` | где блок: индекс в `script.blocks`, затем в `blocks` каждого «Повторить» (`[1, 0]` — первый блок внутри второго). Нужен, только если у двух блоков оказался один `id`; `null` вне блоков |
| `field` | поле в данных страницы (`input`, `press`, `ms`, `minMs`, `maxMs`, `count`, `blocks`, `id`, `type`, а для сценария целиком — `blocks`, `count`, `stepDelay`); `null` — без конкретного поля |
| `message` | готовый текст для пользователя |

Порядок — сверху вниз, первая ошибка совпадает с той, что покажет `toast` при запуске.
Сообщения:

| Где | `field` | Сообщение |
| --- | --- | --- |
| сценарий | `blocks` | Добавьте в сценарий хотя бы один блок |
| сценарий | `blocks` | Все блоки сценария выключены |
| сценарий | `count` | Количество прогонов должно быть не меньше 1 |
| сценарий | `stepDelay` | Пауза между шагами не может быть отрицательной |
| «Нажать», «Зажать», «Отпустить», «Удержать» | `input` | Выберите клавишу или кнопку мыши |
| «Ждать клавишу» | `input` | Выберите клавишу |
| «Отпустить» | `held` | Выше по сценарию ничего не зажато / W не зажата выше по сценарию (сверху вниз по включённым блокам, как они стоят в списке) |
| «Ввести текст» | `text` | Пустой текст |
| «Ввести текст» | `ms` | Пауза между символами не может быть отрицательной |
| «Прокрутить» | `count` | Прокрутите хотя бы на один щелчок |
| «Переместить» | `ms` | Время перемещения не может быть отрицательным |
| «Случайно одно из» | `blocks` | Внутри нет включённых блоков |
| «Нажать» | `press` | Длительность нажатия не может быть отрицательной |
| «Ждать», «Удержать» | `ms` | Время ожидания не может быть отрицательным |
| «Ждать» | `minMs` | Минимальное время ожидания не может быть отрицательным |

| «Повторить» | `count` | Количество повторов должно быть не меньше 1 |

| любой | `id` | У блока нет id / Такой id уже есть у другого блока |
| неизвестный | `type` | Этот блок не поддерживается этой версией GhostClick |

Проблемы остального профиля (например, режим «Удержание» без клавиши «Старт / Стоп») тоже
приходят в `issues`, с `block: null` и текстом, как в уведомлениях кликера.

## Что появится позже

Модель рассчитана на новые типы блоков без смены формата: условия вроде «Ждать цвет пикселя» —
новый `type` со своими полями (точка, цвет, тайм-аут); блоки с вложенными блоками (будущие
«Если» / «Повторять, пока») устроены как «Повторить» — через поле `blocks`.

Поэтому интерфейс рисует блок по `type`, имеет запасной вид для незнакомого типа (название
`type`, заметка, переключатель, удаление), а вложенность определяет по `repeat` / `random`.
